# Dyar Connect — دراسة بناء نظام اتصالات ولوحة تحكم مملوكة بالكامل

> **الهدف:** الحصول على كل ميزات Zello Work (خطة Plus / الشركات) وأكثر منها، بنظام مملوك 100% لديار،
> يعمل على Android و iPhone وأجهزة UR5 والمتصفح والكمبيوتر — **بدون أي اشتراك شهري لكل مستخدم**.

---

## 1. الملخص التنفيذي

Zello Work ممتاز وظيفيًا لكنه نموذج تسعير "لكل مستخدم شهريًا"، وهذا قاتل اقتصاديًا عند التوسع:

| السيناريو | Zello Core ‏($8/مستخدم) | Zello Plus ‏($15/مستخدم) | Dyar Connect (مملوك) |
|---|---|---|---|
| 50 موصل | $400/شهر | $750/شهر | ~$25/شهر بنية تحتية |
| 300 موصل | $2,400/شهر | $4,500/شهر | ~$60/شهر بنية تحتية |
| 300 موصل / سنة | ~$28,800 | ~$54,000 | **أقل من $800** |

الفارق السنوي عند 300 مستخدم: **توفير يتجاوز $28,000 سنويًا** مقابل خادم واحد قوي.
كل المكوّنات المقترحة في هذه الدراسة **مفتوحة المصدر ومجانية بالكامل** (رخص Apache/MIT/BSD) وتُستضاف على خوادمنا.

التكلفة الحقيقية الوحيدة هي **تطوير النظام مرة واحدة** — وبما أن Dyar تملك أصلًا حسابات المستخدمين والسائقين والطلبات والمتاجر، فنحن لا نبني تطبيق PTT منفصل، بل **طبقة اتصالات فوق البنية الموجودة**، وهذا يعطينا ميزات لا يستطيع Zello تقديمها أصلًا (ربط المكالمة بالطلب، AI Dispatcher، قنوات مؤقتة لكل طلب).

## 2. ما الذي نبنيه بالضبط

```
                        DYAR CONNECT
                             │
                  ┌──────────┴──────────┐
                  │    Dyar Identity     │  ← نفس حساب Dyar الحالي
                  │  user / driver ID    │     (لا حسابات جديدة)
                  └──────────┬──────────┘
                             │
           ┌─────────────────┼─────────────────┐
           │                 │                 │
        iPhone            Android          الكمبيوتر
     تطبيق ديار         UR5 + الهواتف      لوحة التحكم (Web)
           │                 │                 │
           └─────────────────┼─────────────────┘
                             │
                     REALTIME GATEWAY
                    (WebSocket + WebRTC)
                             │
           ┌───────────┬─────┴─────┬───────────┐
          PTT         Chat        GPS        Emergency
           └───────────┴─────┬─────┴───────────┘
                             │
                        DYAR BRAIN
                   AI + الطلبات + الأسطول
```

أربعة منتجات فرعية:

1. **Dyar Connect Server** — الخادم (صوت، رسائل، حضور، مواقع، تسجيل).
2. **لوحة التحكم / Dispatch Console** — موضوع هذه الدراسة، انظر [docs/dashboard-spec.md](docs/dashboard-spec.md) والنموذج التفاعلي في [prototype/dashboard.html](prototype/dashboard.html).
3. **تطبيق السائق** — Android خفيف (يشمل UR5) + iPhone.
4. **Dyar Servo UR5 Edition** — نسخة مخففة جدًا لأجهزة 1GB RAM.

## 3. مطابقة ميزات Zello Work — بند ببند

فحصنا لوحة إدارة Zello Work فعليًا (شبكة dyarapp التجريبية). هذه كل الأقسام الظاهرة فيها وكيف نغطيها:

| قسم في لوحة Zello | ماذا يفعل | مقابله في Dyar Connect |
|---|---|---|
| **Map** | مواقع حية، فلترة، أقمار صناعية، ازدحام | خريطة MapLibre + OSM، تحديث لحظي عبر WebSocket، طبقة طلبات فوق السائقين |
| **Message Vault** | أرشيف كل المكالمات والرسائل (خطة Plus) | تسجيل كل بث PTT إلى MinIO + فهرسة وبحث، **بدون حد زمني وبدون رسوم** |
| **AI Digests** | ملخصات ذكية للمحادثات | تفريغ صوتي (Whisper محلي) + تلخيص عبر Dyar Brain |
| **Ella (AI Assistant)** | مساعد يجيب عن أسئلة | AI Dispatcher يعرف الطلب والسائق والموقع — أقوى من Ella لأنه متصل بالتشغيل |
| **Users** | إضافة/حذف/حالة | يُدار من حسابات Dyar الموجودة — لا إدارة مزدوجة |
| **User Templates** | قوالب صلاحيات | أدوار: Admin / Supervisor / Dispatcher / Driver / Merchant |
| **Channels** | قنوات جماعية + Emergency | قنوات ثابتة (مناطق: البعنة، دير الأسد، مجد الكروم، كرمئيل…) + **قنوات مؤقتة تلقائية لكل طلب** |
| **Gateways** | ربط أجهزة راديو خارجية | مؤجل — غير مطلوب حاليًا (لا نملك أجهزة راديو تقليدية) |
| **Dispatch Analytics** | إحصاءات المكالمات والاستجابة | لوحة تحليلات: زمن استجابة، حجم البث، ذروة النشاط، لكل قناة وسائق |
| **Sign In Report** | تقرير تسجيلات الدخول | جدول جلسات: جهاز، إصدار، IP، مدة الاتصال |
| **Audit Log** | سجل إجراءات المشرفين | سجل تدقيق غير قابل للتعديل لكل إجراء إداري |
| **Emergency / Panic** | زر طوارئ (خطة Plus) | Priority Voice ثلاثي المستويات + فتح GPS وتسجيل تلقائي — انظر §6 |
| **Dispatch Hub** | طوابير مكالمات ومحادثات 1:1 | مدمج في لوحة التحكم نفسها + مرتبط بالطلب الجاري |

وما **لا يستطيع** Zello فعله ونضيفه نحن:

- **الموزّع الذكي**: Brain يستقبل الطلب الجديد، يحسب أقرب موصل مناسب (مسار طريق فعلي + الحمل + عدالة التوزيع)، يناديه صوتيًا عبر اللاسلكي، يأخذ قبوله بضغطة PTT أو بكلمة، ويسند الطلب — التفاصيل في [docs/ai-dispatcher.md](docs/ai-dispatcher.md).
- ربط كل اتصال بالطلب الجاري للسائق (`ORDER-18291`).
- AI يفهم "المطعم يقول الطلب سيتأخر عشر دقائق" → يحدّث الطلب ويعيد حساب ETA ويسجل الحادثة تلقائيًا.
- قناة مؤقتة لكل طلب تجمع الموصل + العمليات + AI وتختفي عند الإغلاق.
- شاشة واحدة فيها: الخريطة + الطلب + البطارية + الشبكة + زر تحدث — بدون تنقل بين نظامين.

## 4. البنية التقنية (كلها مجانية ومفتوحة المصدر)

التفاصيل الكاملة في [docs/architecture.md](docs/architecture.md). الخلاصة:

| الطبقة | التقنية | الرخصة | البديل التجاري الذي توفّره |
|---|---|---|---|
| الصوت الحي (SFU) | **LiveKit** (self-hosted) | Apache-2.0 | بنية Zello الصوتية |
| الترميز الصوتي | **Opus** ‏(~16kbps للكلام) | BSD | نفس ما يستخدمه Zello |
| NAT/جدران الحماية | **coturn** (TURN/STUN) | BSD | — |
| الإشارات والحضور | **WebSocket** ‏(Node.js/TypeScript) | MIT | — |
| مواقع GPS | **MQTT (EMQX)** أو WebSocket | Apache-2.0 | خرائط Zello الحية |
| الخرائط | **MapLibre GL + OpenStreetMap** | BSD/ODbL | Google Maps (بدون فاتورة API) |
| قاعدة البيانات | **PostgreSQL** | PostgreSQL | — |
| الحالة اللحظية | **Redis** | BSD | — |
| أرشيف الصوت والصور | **MinIO** ‏(متوافق S3) | AGPL | Message Vault |
| تفريغ الصوت | **faster-whisper** (محلي) | MIT | Zello Transcription (خطة Plus) |
| الإشعارات | **FCM + APNs** | مجانية | — |
| تطبيق Android/UR5 | **Kotlin** ‏(minSdk 26) | — | تطبيق Zello |
| تطبيق iPhone | **Swift** | — | تطبيق Zello |
| لوحة التحكم | **React + MapLibre** | MIT | Dispatch Hub |

> **لماذا LiveKit وليس بناء WebRTC من الصفر؟** LiveKit يعطينا SFU جاهزًا مع SDK رسمية لـ Android/iOS/Web،
> ويُستضاف على خادمنا بالكامل. نبني فوقه منطق PTT (احجز القناة → تكلم → حرر) بدل أن نبني محرك صوت من الصفر.
> هذا يختصر شهورًا من التطوير ويبقى الكود والبيانات عندنا.

## 5. دعم جهاز UR5 (الموجود فعليًا بين أيدينا)

فحص الجهاز: **Siyata UR5** — ‏Android 8.1 (API 27)، ذاكرة 1GB، مودم SIM8905، أزرار فيزيائية (PTT / SOS / FN).

| القيد | الحل |
|---|---|
| Android 8.1 | ‏minSdk 26 في تطبيق السائق — مدعوم رسميًا في LiveKit Android SDK |
| ذاكرة 1GB | نسخة "UR5 Edition": بدون خرائط داخل الجهاز، واجهة قائمة واحدة، صوت + GPS فقط |
| زر PTT الفيزيائي | التقاط KeyEvent / Broadcast الخاص بالجهاز (يُحدد بالفحص العملي — أجهزة Siyata تبث Intent عند الضغط) |
| زر SOS | يُربط مباشرة بمسار الطوارئ (Priority 3) |
| شاشة صغيرة | التصميم: شاشة واحدة — اسم القناة + من يتكلم الآن + حالة الشبكة والبطارية |
| Google Play قديم | التوزيع بملف APK مباشر + تحديث ذاتي داخل التطبيق (لا حاجة للمتجر) |

ملاحظة: Zello نفسه ما زال يدعم Android 7+، أي أن فئة الأجهزة هذه قابلة للخدمة تقنيًا — المهم فقط خفة التطبيق.

## 6. Priority Voice — ميزة تتفوق على Zello

كل بث صوتي يحمل أولوية:

```
Priority 1 — بث عادي            → طابور عادي في القناة
Priority 2 — مشكلة طلب          → يعلو الطابور + إشعار للمشرف + يُربط برقم الطلب
Priority 3 — طوارئ (زر SOS      → يقطع أي بث جارٍ فورًا
              أو كلمة "حادث")     + فتح GPS مباشر للسائق
                                  + تسجيل تلقائي للصوت
                                  + تنبيه صوتي في لوحة التحكم وكل المشرفين
```

هذه وظيفة يدفع Zello مقابلها في خطة Plus (Emergency Alerts) — عندنا تكون قياسية ومربوطة بالطلب والموقع.

## 8. خطة التنفيذ — MVP ثم التوسع

### المرحلة 1 — MVP (إثبات جودة الصوت) — 6 عناصر فقط
1. تسجيل دخول بحساب Dyar الحالي (JWT الموجود).
2. حضور Online/Offline لحظي.
3. ‏PTT فردي 1:1.
4. قناة "Dyar Operations" جماعية واحدة.
5. زر UR5 الفيزيائي يعمل.
6. لوحة تحكم ويب أولية: قائمة المتصلين + زر تحدث.

**معيار النجاح:** زمن من الضغط حتى وصول الصوت < 500ms على 4G، وثبات ساعة عمل متواصلة على UR5.

### المرحلة 2 — التشغيل الميداني
- خريطة حية + GPS، قنوات المناطق، رسائل نصية وصور، Replay، حالة البطارية.

### المرحلة 3 — لوحة التحكم الكاملة
- كل شاشات [docs/dashboard-spec.md](docs/dashboard-spec.md): الأرشيف، التحليلات، سجل الدخول، سجل التدقيق، إدارة الأدوار.

### المرحلة 4 — الذكاء والتفوق
- Priority Voice، القناة المؤقتة لكل طلب، تفريغ صوتي وتلخيص، AI Dispatcher، اكتشاف التأخير آليًا.

## 9. المخاطر وكيف نتعامل معها

| الخطر | التخفيف |
|---|---|
| جودة الصوت على شبكات ضعيفة | Opus بمعدل متكيف + إعادة إرسال محدودة + اختبار ميداني مبكر في المرحلة 1 |
| استهلاك بطارية UR5 | Foreground Service واحد، لا خرائط على الجهاز، ضبط فاصل GPS حسب الحركة |
| التقاط زر PTT على UR5 | مهمة استكشاف عملية في أول أسبوع — إن تعذر، نستخدم زر الشاشة مؤقتًا |
| موثوقية الخادم الواحد | نسخ احتياطي يومي + توثيق استعادة؛ لاحقًا خادم احتياطي عند تجاوز حجم معين |
| iOS في الخلفية (قيود Apple على PTT) | استخدام إطار PushToTalk الرسمي من Apple ‏(iOS 16+) المصمم لهذا الغرض تحديدًا |
