# Dyar Executive Brain — عقل ديار التنفيذي

ليس Chatbot على تلفاز: **العقل الحقيقي يعيش على الخادم** (`server/src/server.js`)، والتلفاز مجرد
وجه له داخل المكتب. نفس العقل — نفس البيانات ونفس الصلاحيات ونفس الأولويات — يُخاطَب من:

| الواجهة | الطريق |
|---|---|
| تلفاز المكتب | `/kiosk.html` (متصفح التلفاز أو صندوق تشغيل صغير عبر HDMI) |
| حاسوب العمليات | لوحة `/` — تبويب **⚡ الأولويات** + كل الإدارة |
| الهاتف / أي جهاز | نفس `/kiosk.html` أو REST (`/api/brain/*` برمز اللوحة) |
| غرفة التشغيل (egint) | أحداث `priority_*` تصل عبر الـWebhook وتظهر إشعارات |

```
                DYAR EXECUTIVE BRAIN (على الخادم)
                          │
              ┌───────────┴───────────┐
      Deterministic Core        Reasoning Layer
      (قواعد/حساب/سياسات)       Claude (اختياري)
              │                       │
              └───────────┬───────────┘
                          │
              Executive Tool Gateway  ← الأدوات typed للقراءة فقط
                          │
   Orders · Fleet · Queue · SOS · Stats · Priorities · Team
                          │
        TV  ·  Dashboard  ·  Phone  ·  غرفة التشغيل
```

## 1) ربط العقل بالحقيقة — Executive Tool Gateway

ممنوع على أي LLM الإجابة عن حالة الشركة من ذاكرته أو لمس الحالة مباشرة.
كل معرفة تمر عبر أدوات typed في `EXEC_TOOLS`:

`getCurrentOperations · getTodayPerformance · getYesterdayPerformance · getFleetStatus ·
getPriorities · getTeamLoad · getOrder(orderId) · getDriver(driver)`

- **بلا مفتاح**: العقل المحلي الحتمي يجيب فوراً من نفس الأدوات (أرقام حقيقية، صفر انتظار).
- **مع `ANTHROPIC_API_KEY`**: Claude (النموذج `claude-opus-5` افتراضياً، يُغيَّر بـ`BRAIN_MODEL`)
  يستدعي الأدوات بنفسه (حتى 4 جولات) ثم يصيغ الجواب كمدير عمليات. أي تعثّر ⟵ رجوع محلي تلقائي.
- كل جواب يحمل `asOf` وتعرضه الشاشة: **DATA AS OF 09:14:32**.
- العقل **يقترح ولا ينفّذ**: الأوامر (إسناد/إلغاء/فصل جهاز) تمر حصراً عبر مسارات اللوحة المحمية.

## 2) محرك الأولويات — Priority & Action Engine

كل حدث مهم يصبح عنصر عمل مُدار حتى النهاية — لا «إشعار ونأمل أن يراه أحد»:

```
DETECT → SCORE → ASSIGN → NOTIFY → ACK → (ESCALATE) → ACTION → VERIFY → CLOSE + OUTCOME
```

**الكواشف** (فورية عند الحدث + كنس كل 10 ثوانٍ):

| النوع | الشرط | الأساس |
|---|---|---|
| `sos` | زر الطوارئ | P0 (95) |
| `no_drivers` | طلبات نشطة و0 موصل متصل | P0 (92) |
| `dispatch` | طلب رفضه الجميع رغم وجود موصلين | P1 (82) |
| `driver_lost` | موصل معه طلب وانقطع ≥3 د | P1 (80) |
| `stuck` | مُسند بلا استلام ≥15 د | P1 (78) |
| `late` | مستلَم بلا تسليم ≥45 د | P1 (72) |
| `queue` | ينتظر موصلاً حراً (يتصاعد مع العمر) | P2⟶P1 (55+4/دقيقة) |
| `cancels` | ≥3 إلغاءات باليوم | P2 (متدرج) |

- **التسعير حسابي لا لغوي** (`score 0-100` ⟵ P0≥90 · P1≥75 · P2≥50 · P3≥25 · P4).
- **أولوية واحدة مفتوحة لكل حالة** (مفتاح ارتباط) — التكرار يحدّث الدرجة فقط (Dynamic Priority).
- **ACK إلزامي**: بلا استلام تتصعد P0 بعد 60/120/240 ث وP1 بعد 2/5/10 د (تذكير ⟵ احتياط ⟵ إدارة)،
  والشاشة تنطق التذكير، وغرفة التشغيل تستلم إشعار التصعيد.
- **تحقق آلي**: «حُلّت» بشرياً والسبب ما زال قائماً ⟵ يعاد فتحها؛ زال السبب ⟵ إغلاق موثّق `verified`.
- **ممنوع الإغلاق بلا نتيجة**: كل إغلاق يسجل `outcome`، وآخر 200 مغلقة محفوظة للمراجعة والتعلم.
- كل خطوة موثقة في `log[]` داخل الأولوية (من فعل ماذا ومتى) + أحداث `priority_*` لغرفة التشغيل.

## 3) شاشة المكتب `/kiosk.html`

- **كلمة التنبيه «يا ديار»**: وضع الاستماع الدائم لا يعالج أي كلام إلا ما جاء بعد «ديار» —
  وأثناء نطق الشاشة تُقبل فقط جمل فيها «ديار» (منع صدى + طريق المقاطعة: «يا ديار، أوقف»).
- ترحيب بالاسم: «أنا أمين» ⟵ «أهلاً بك المدير أمين» (الطاقم من `KIOSK_STAFF`).
- **LIVE PRIORITIES** لحظية عبر WebSocket، مع زر «استلمت/حُلّت» وصوت «يا ديار، استلمت».
- P0 مفتوحة ⟵ وضع الإنذار: إطار أحمر نابض + شريط OPERATIONAL ATTENTION REQUIRED + نطق التنبيه.
- KPIs حية (اليوم/أمس/نشط/في الخطر/متصلون/أولويات) + ساعة وتاريخ عربي + DATA AS OF.
- أسئلة صوتية أو نصية: «كم طلبية أمس؟ ما المشاكل؟ شو عندي؟ مين عليه ضغط؟ ما برنامج اليوم؟».
- زر 🌐 لغة التعرف/النطق (عربي/عبري/إنجليزي) — إجابات العقل المحلي بالعربية، وClaude يجيب باللغات الثلاث.
- **🔒 وضع الخصوصية**: يموّه لوحتي الأولويات والجواب ويكتم النطق (زبائن في المكتب).
- لا Keyboard مطلوب: ريموت التلفاز (OK) يبدأ الاستماع، وحقل نصي احتياطي لتلفاز بلا مايكروفون.

> **توصية العتاد**: الأفضل صندوق تشغيل صغير (Mini PC/Android Box) موصول بالتلفاز عبر HDMI
> ومعه مايكروفون وسماعة، والتلفاز شاشة عرض فقط — يُستبدل التلفاز دون تغيير النظام.
> التعرف الصوتي يستعمل محرك المتصفح (Chrome) — للـSTT محلي بالكامل لاحقاً: صندوق مخصص بمحرك مفتوح.

## 4) الحدود الواضحة (لا نقطة فشل واحدة)

- تعطل Claude ⟵ العقل المحلي يستمر بنفس الأدوات. تعطل التلفاز ⟵ اللوحة وغرفة التشغيل تستمران.
- تعطل العقل كله ⟵ تاليا والإسناد والطابور والبوابة تستمر (العقل طبقة قيادة، ليس مصدر الحقيقة).
- الحالة بالذاكرة (إعادة التشغيل تصفّر الأولويات المفتوحة — تُعاد فتح ما سببه قائم خلال ≤10 ث
  بفضل الكواشف). الأرشيف الدائم والتقارير التاريخية ⟵ مرحلة PostgreSQL.

## 5) متغيرات البيئة الجديدة

| المتغير | الوظيفة |
|---|---|
| `ANTHROPIC_API_KEY` | اختياري — يفعّل استدلال Claude (بدونه: العقل المحلي) |
| `BRAIN_MODEL` | اختياري — النموذج (افتراضي `claude-opus-5`) |
| `KIOSK_STAFF` | اختياري — طاقم المكتب JSON: `[{"name":"أمين","title":"المدير","role":"management"}]` |
| `OPS_PIN` | رمز اللوحة والشاشة (كان موجوداً — الشاشة تستعمله) |

## 6) REST للواجهات

كلها برمز اللوحة (`x-kiosk-pin` للقراءة، `pin` في الجسم للكتابة):

```
GET  /api/brain/summary          ← KPIs + أولويات + حمل فريق + طاقم
POST /api/brain/ask              ← {pin, q, staff} ⟵ {answer, source, asOf}
GET  /api/brain/priorities       ← المفتوحة + آخر المغلقة بنتائجها + الحمل
POST /api/brain/priority-action  ← {pin, id, action: ack|start|resolve|reassign, who, note}
```

## 7) المرحلة التالية (مرتبة بالأثر)

1. **PostgreSQL**: أرشيف الطلبات والأولويات والقرارات ⟵ إحاطة صباحية تاريخية وSelf-Evaluation كامل.
2. **بصمة صوت + PIN للإجراءات الحساسة** (الإلغاء/الاسترداد = Level 4 بتأكيد إضافي).
3. **إشعارات هاتف شخصية** لكل موظف (Push) مع Handoff بين الورديات.
4. **War Room Mode** للحوادث الكبيرة + Postmortem آلي.
5. **Forecast Agent**: توقع ضغط الساعة القادمة من تاريخ الطلب ⟵ أولويات وقائية قبل المشكلة.
